# 证据规范

## 证据边界

先声明可证明和不可证明的内容。只有一手公开页面、可复现的实时观察、用户导出或付费工具原始数据才能支持事实性主张；模型生成的候选、搜索摘要和推断只能作为发现入口或假设。

| 证据类型 | 可以支持 | 不能单独证明 |
|---|---|---|
| 搜索/趋势 | 查询语言、相对变化、季节性、相关主题 | 精确搜索量、付费意愿 |
| 社区痛点 | 用户原话、任务频率、现有 workaround | 市场规模、代表性 |
| 商业证明 | 已有定价、付费产品、采购动作 | 用户满意度、可复制收入 |
| 竞品公开页 | 定位、功能、价格、目标用户 | 实际流量、排名、收入 |
| 分发信号 | 可触达社区、目录、平台或搜索意图 | 获客成本、转化率 |
| 技术变化 | 新能力、成本变化、平台开放 | 持续需求、商业可行性 |
| 付费/自有导出 | 工具字段直接表达的估算或自有表现 | 工具未覆盖的真实世界结果 |

## 独立信号

多个页面复述同一原始消息只算一个信号。每个 finalist 需要三类独立支持信号。背景、反对证据和 low reliability 线索不计入支持门槛；同一原始来源只能贡献一个独立信号。优先组合“行为/搜索 + 用户原话 + 商业证明”，再用竞争和分发证据解释切入点。

## evidence.jsonl

每行一个 JSON 对象，必填字段：

- `id`：`E001` 起的稳定 ID；
- `source_url`、`source_title`、`collected_at`；
- `source_type`：如 `official`、`public-web`、`public-serp`、`community`、`paid-tool`、`user-export`；
- `signal_family`：如 `search-trend`、`community-pain`、`commercial-proof`、`competitor-gap`、`distribution`、`technology-shift`；
- `direction`：`support`、`counter` 或 `context`；
- `claim`：该来源实际支持的一条主张；
- `excerpt`：保留原文的短摘录；
- `reliability`：`low`、`medium` 或 `high`；
- `limitations`：样本、时间、地域、登录态、估算或可重复性限制。

可选 `source_group` 标识共同的原始来源；转载、镜像或同一调查的不同页面应填写同一个值。脚本默认按 URL 去重，无法自动发现隐含的同源关系；采集者负责核实来源独立性。字段必须有实际内容，不能靠类别标签把一条消息拆成多个信号。

## 禁止性表述

- 没有对应字段的原始数据时，不写精确搜索量、排名、流量、收入、转化率或关键词难度。
- Google Trends 指数只能称为相对兴趣，不换算搜索量。
- 公开页面只能说明“竞品公开定位/定价”，不能说明其实际增长或收入。
- 社区帖只能证明具体发帖者表达过痛点，不能自动外推整个市场。
- 报告中的推断必须标成假设，并给出下一步验证方法。

## 隐私

付费工具导出、登录内容和用户私有数据不得写入公开插件仓库、示例或测试夹具。公开报告引用私有来源时只保留用户允许披露的聚合结论。
